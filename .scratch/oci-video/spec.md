# 설명 영상: 도메인·OCI 배포와 Windows/macOS 클라이언트

Status: ready-for-agent

과제: 치지직 만들기 ⑥ "도메인·OCI 배포와 Windows/macOS 클라이언트" (설명 영상 제작).
도메인을 사서 OCI 서버에 배포한 과정과, Windows·macOS 앱을 빌드한 과정을 설명 영상 한 편으로 만든다.
개인정보는 화면에 나오지 않게 하고, 실제 사이트(`duse.dev`, `live.duse.dev`) 화면을 예시로 쓴다.

## 개인정보 규칙

화면, 코드 카드, 터미널 출력, 자막 어디에도 아래가 나오면 안 된다. 나오면 흐림 처리하거나 그 부분을 잘라 낸다.

- 이름, 이메일, 주소, 전화번호, 카드 정보 (OCI·Cloudflare·결제 화면)
- OCI 계정(테넌시) 이름, OCID, 테넌시 정보
- 서버 공인 IP, SSH 키 경로·내용, `.env` 비밀값, 토스 키, DB 비밀번호
- Mac 사용자 이름이 보이는 경로(`/Users/...`), 터미널 프롬프트의 사용자·호스트 이름
- GitHub 사용자 이름 (저장소 이름 부분만 남긴다)
- macOS 메뉴 막대·알림, Windows 작업 표시줄의 계정 정보

보여도 되는 것: 도메인(`duse.dev`, `live.duse.dev`, `s.duse.dev`), 실제 사이트 화면, 데모 계정의 닉네임.

터미널 장면은 프롬프트를 `$`만 남긴 깨끗한 셸에서 찍고, IP가 출력되는 명령은 출력을 `<서버 IP>`로 바꿔 보여 준다.

### 0. 인트로 (20초)

- 과제 제목과, 완성된 결과 미리보기: `duse.dev` 첫 화면 → `live.duse.dev`에서 라이브 재생 중인 화면.
- "도메인을 사서 OCI 무료 서버에 올리고, Windows·macOS 앱까지 만든 과정"이라고 한 문장으로 소개한다.

### 1. 도메인 (60초)

- Cloudflare Registrar에서 구매한 이유: 원가 판매, DNS 관리 무료. 첫해 할인과 갱신가 차이.
- `.dev`를 고른 이유와 그 결과: 브라우저가 **HTTPS만 허용**(HSTS preload)하는 도메인이라 인증서가 필수가 된다 → 장면 4의 Caddy로 이어진다.
- DNS 레코드 두 개: `@`(`duse.dev` 자체)와 `*`(모든 서브도메인). 와일드카드가 `duse.dev` 자체를 포함하지 않아서 둘 다 필요하다.
- 프록시(주황 구름)를 끈 이유: WebRTC 미디어(8189)는 Cloudflare를 거칠 수 없고, 무료 요금제는 영상 대량 전달을 약관으로 제한한다.
- 화면: Cloudflare DNS 레코드 목록 캡처(가림), `dig duse.dev`, `dig 아무거나.duse.dev`가 같은 IP를 돌려주는 터미널(IP는 `<서버 IP>`).

### 2. OCI 서버 기본 개념 (120초)

리전 → VCN → 서브넷 → 인스턴스를 겹친 도식 한 장을 두고, 개념마다 해당 부분을 강조한다. 개념마다 "이 프로젝트에서는 이렇게 정했다"를 붙인다.

1. **리전·가용성 도메인**: 도쿄 리전. 가용성 도메인이 하나뿐이라 자리가 없으면 다른 곳으로 피할 수 없다.
2. **컴파트먼트**: 자원을 담는 폴더. 루트 하나만 쓴다.
3. **VCN·서브넷·인터넷 게이트웨이**: 서버가 사는 가상 네트워크와 공인 서브넷. 인스턴스 생성 화면에서 새 VCN을 함께 만들면 공인 IP 스위치가 잠겨서, VCN 마법사로 먼저 만들었다.
4. **인스턴스·셰이프**: `VM.Standard.A1.Flex`(ARM, Ampere). 상시 무료 범위(A1 합계 2 OCPU / 12GB. 2026년에 4 OCPU / 24GB에서 절반으로 줄었다. 영상에서는 합계를 말하지 않는다). 처음엔 "Out of capacity"로 생성이 계속 실패했고 1 OCPU / 6GB로 만들었다. ARM이라 Docker 이미지도 arm64여야 한다.
5. **부트 볼륨·공인 IP·SSH 키**: 디스크, 고정 주소, 비밀번호 대신 키로 접속.
6. **방화벽 2겹**: OCI 보안 목록(서버 바깥)과 iptables(서버 안). Ubuntu 이미지는 기본으로 22만 열려 있어서 **둘 다** 80, 443, 8189를 열어야 접속된다.

화면: 도식, OCI 인스턴스 상세 캡처(A1.Flex, "상시 무료 적격", 실행 중. OCID·IP·계정명 가림), 보안 목록 수신 규칙 캡처(22, 80, 443, 8189).

### 3. 비용 안전장치 (15초)

- 한 장의 도식에 세 줄로: 할당량 정책(무료 셰이프만 생성 허용), $1 예산의 1% 알림, 송신 29 Mbit/s 상한(한 달 내내 써도 무료 10TB 안).
- 계산 과정이나 설정 화면은 보여 주지 않는다.

### 4. Caddy와 배포 (120초)

1. **리버스 프록시**: 443 하나로 받아서, 주소와 경로를 보고 안쪽 서비스로 나눠 주는 문지기.
2. **자동 HTTPS**: Let's Encrypt 인증서 발급·갱신을 Caddy가 알아서 한다. `.dev`라 필수. 터미널에서 실제 인증서의 발급자와 만료일을 보여 준다.
3. **자동 이동**: `http://` → `https://`, `www.duse.dev` → `duse.dev`. 터미널에서 응답 코드(308, 301)로 보여 준다.
4. **`live.duse.dev` 경로 분배**: compose 시절 Caddyfile을 코드 카드로 보여 주고, 요청이 Caddy를 거쳐 각 컨테이너로 가는 흐름을 애니메이션으로 보여 준다.
   - `/api`, `/media` → API 서버
   - `/hls` → 접두사를 떼고 MediaMTX로. MediaMTX가 돌려주는 리다이렉트 주소에는 `/hls`를 다시 붙인다
   - `/whip` → 접두사를 떼고 MediaMTX 송출로
   - `/api/internal` → 404로 밖에서 차단
   - 나머지 → React 앱(새로고침해도 `index.html`)
5. **왜 nginx가 아니라 Caddy**: 인증서를 따로 관리할 필요가 없고 설정이 짧다. README의 배포 안내는 원래 nginx 기준이었다.
6. **compose 운영 덮어쓰기**: `compose.prod.yaml` 코드 카드. 내부 포트를 `127.0.0.1`에만 열어 Caddy만 들어오게 한다. Docker가 연 포트는 iptables를 우회한다는 함정. 비밀값은 git이 아닌 서버 `.env`에 둔다.
7. **실 사이트 시연**: `live.duse.dev`에서 데모 방송 라이브 시청, VOD 재생.

화면에 쓰는 git 기록 파일(커밋 `7b9a4aa`, `3c0982b` 시점): `compose.prod.yaml`, `deploy/Caddyfile`. 비밀값은 원래 없지만, IP가 들어간 줄은 `<서버 IP>`로 바꾼다.

### 5. 도메인 하나, 여러 서비스 (15초)

- `duse.dev` 상태 카드 화면을 그대로 보여 준다. 서브도메인과 Caddy 블록을 하나 더하면 서비스를 붙일 수 있다는 한 문장.
- 단축 URL(`s.duse.dev`)은 "다른 프로젝트"라고만 짧게 말한다. `live-on`/`live-off`는 한 줄 언급.

### 6. Windows/macOS 앱 (90초)

- Dioxus 코드 하나로 Windows(WebView2)·macOS(WKWebView) 앱을 만든다. 웹과 같은 서버 API를 쓴다.
- GitHub Actions가 태그(`desktop-v*`)를 받으면 Windows `.msi`와 macOS `.dmg`를 빌드해 Release에 올린다. Actions 실행 결과 캡처(GitHub 사용자 이름 가림).
- 다운로드 페이지(`live.duse.dev/download/`) 자동 촬영. 큰 파일은 GitHub Releases로 넘겨서 서버 송신량을 쓰지 않는다는 한 문장.
- **macOS**: DMG 설치 → 실행 → 라이브 시청 → VOD 재생 (사용자 녹화).
- **Windows**: 교체 자리.
  - `presentation/oci-deploy/video/assets/media/windows-run.mp4`가 **없으면**: 빌드된 `.msi` 파일과 다운로드 페이지까지 보여 주고, 자막 "Windows 실행 화면은 추가 예정".
  - **있으면**: 그 녹화본을 넣고 내레이션을 "Windows에서도 같은 기능이 동작합니다"로 바꾼다.
  - 녹화본을 넣고 다시 렌더하는 것만으로 교체가 끝나야 한다. 녹화 순서는 [windows-recording-guide.md](windows-recording-guide.md).

### 7. 마무리 (15초)

- 확인한 것과 아직 확인하지 않은 것을 카드 한 장으로. Windows 녹화본이 없으면 "Windows 실행 확인 예정"이 여기에 들어간다.
- 다음 영상 예고는 넣지 않는다.

## 터미널에서 다시 실행할 확인 명령

모두 K3s와 무관하게 지금도 같은 결과가 나오는 것만 쓴다.

| 장면 | 확인 | 보여 줄 결과 |
| --- | --- | --- |
| 1 | `dig +short duse.dev`, `dig +short 아무거나.duse.dev` | 같은 `<서버 IP>` |
| 4 | 인증서 확인(`openssl s_client`) | 발급자 Let's Encrypt, 만료일 |
| 4 | `curl -I http://duse.dev`, `curl -I https://www.duse.dev` | 308 → https, 301 → duse.dev |
| 4 | `curl -I https://live.duse.dev/api/internal/...` | 404 |
| 2 | 내부 포트(5432, 8180, 8888, 8889)에 밖에서 접속 | 모두 막힘 |
| 3 | (보여 주지 않음) | |

## 사용자에게 요청할 일 (순서대로)

1. **데모 계정 2개 가입**: `live.duse.dev`에서 방송자 `데모방송`, 시청자 `데모시청자` (실명과 무관한 이메일·닉네임). 비밀번호는 직접 관리.
2. **콘솔 로그인**: 캡처할 때 내장 브라우저에서 Cloudflare와 OCI에 로그인. 캡처와 가림 처리는 에이전트가 한다.
3. **macOS 앱 녹화**: 에이전트가 장면 목록을 주면 QuickTime으로 녹화(DMG 설치 → 실행 → 라이브 → VOD). 그동안 에이전트가 데모 방송을 송출해 둔다.
4. **결과 확인**: 초안 mp4를 보고 고칠 점을 알려 준다.
5. **(나중에) Windows 녹화**: [windows-recording-guide.md](windows-recording-guide.md)대로.

## 확인이 필요한 사실

- 가짜 카메라로 쓸 쇼츠 영상의 출처·저작권. 문제가 있으면 직접 만든 영상이나 저작권이 자유로운 영상으로 바꾼다.
- 현재 서버의 Caddyfile·포트·송신 상한이 compose 시절과 같은지(터미널 장면이 ⑥ 설명과 맞는지).
- GitHub Actions `desktop-v0.1.0` 빌드 기록이 아직 남아 있는지.
