# 07. 회원 탈퇴

Status: resolved (2026-11-27, 브랜치 `content-report`, 아직 커밋 전)

스토어 심사 준비(`../spec.md`)의 A-4 항목이다. 나중에 영상으로 만들 때 이 문서를 대본 재료로 쓴다.

## 한 줄 요약

웹과 앱의 **"내 계정"** 화면에서 비밀번호를 다시 넣으면 바로 탈퇴된다. 탈퇴하면 그 회원의 모든 것을 한 번에 지우고, 모든 기기의 로그인을 끊는다.

## 왜 만들었나

- **Google Play 계정 삭제 정책**: 계정을 만들 수 있는 앱은 **앱 안과 웹 양쪽**에서 계정을 지울 수 있어야 한다. 계정 정지나 비활성화는 삭제로 인정하지 않는다.
- **개인정보 보호법**: 회원은 삭제를 요구할 수 있다.
- 06의 약관·방침에는 "탈퇴 기능을 준비하는 동안 이메일로 요청"이라고 적어 두었다. 이제 그 문구를 실제 기능으로 바꾼다.
- Microsoft Store 정책에는 일반 앱의 계정 삭제 요구가 없다. 하지만 같은 앱을 Play에도 올리므로 함께 만든다.

## 정한 규칙 (사용자와 결정, 2026-11-27)

| 항목 | 결정 | 이유 |
|---|---|---|
| 지우는 범위 | **전부 지운다**. 아래 "지우는 것" 표 참고 | 개인정보처리방침 문구와 그대로 맞고 구현이 단순하다. 후원은 지금 테스트 결제라 상대방 내역에서 사라져도 문제없다 |
| 확인 | **비밀번호 다시 입력** + "되돌릴 수 없다는 것을 확인했습니다" 체크 | 열어 둔 화면을 다른 사람이 눌러도 탈퇴되지 않게 한다 |
| 운영자 | 탈퇴 불가(400). 역할을 해제한 뒤 가능 | 운영자가 사라지면 처리 기록의 처리자가 비게 된다 |
| 정지된 회원 | 로그인할 수 없으므로 이메일로 요청 | 약관 제13조 |
| 아이디 | 지운 뒤 같은 아이디로 다시 가입할 수 있다 | 행을 실제로 지운다 |

### 지우는 것

| 대상 | 방법 |
|---|---|
| 계정(아이디, 닉네임, 비밀번호 해시, 동의 기록) | `app_user` 행 삭제 |
| 유튜브 키 | `simulcast_setting`이 계정과 함께 지워진다(외래 키 cascade) |
| 올린 동영상 | 행 삭제, **원본·변환·썸네일 파일은 커밋 뒤 삭제**. 운영자가 내린 것도 지운다 |
| 방송 | 행 삭제(진행 중이면 다음 동기화 때 송출이 끊긴다) |
| 내가 쓴 댓글 | 다른 사람의 콘텐츠에 단 것까지 전부 |
| 내 동영상·방송에 남이 단 댓글 | 콘텐츠와 함께 지워진다(외래 키 cascade) |
| 후원 | 보내거나 받은 것 모두. 상대방 내역에서도 사라진다 |
| 내가 한 신고 | 삭제. 내가 처리한 신고의 처리자(운영자)는 비운다 |
| 로그인 | 모든 기기의 세션 삭제, 지금 요청의 세션 무효화 |

**남기는 것**: 다른 사람이 내 콘텐츠를 신고한 기록. 신고한 사람의 기록이기 때문이다. 대상 콘텐츠는 지워진 상태로 보인다("작성자가 이미 지운 …").

## 서버

### API

`POST /api/auth/withdraw` (로그인과 CSRF 토큰 필요)

```json
{ "password": "…" }
```

| 결과 | 응답 |
|---|---|
| 성공 | 204, 세션 무효 |
| 로그인 안 함 | 401 |
| 비밀번호 틀림 | 400 "비밀번호가 올바르지 않습니다." (아무것도 지우지 않음) |
| 운영자 | 400 "운영자 계정은 탈퇴할 수 없습니다. 먼저 운영자 역할을 해제해 주세요." |

### 코드

- `withdrawal/WithdrawalService.java`
  - 비밀번호 확인과 운영자 확인을 한다.
  - 그다음 **외래 키 순서대로 한 트랜잭션에서** 지운다: 쓴 댓글 → 후원 → 신고 → 방송 → 동영상 → 계정.
  - 마지막으로 그 아이디의 모든 세션을 지운다(Spring Session `FindByIndexNameSessionRepository`).
- 각 서비스의 삭제 메서드
  - `CommentService.deleteAllWrittenBy`
  - `DonationService.deleteAllOf`
  - `ReportService.forget`
  - `BroadcastService.deleteAllOwnedBy`
  - `VideoService.deleteAllOwnedBy`: 파일은 `TransactionSynchronization.afterCommit`에서 지운다. DB 삭제가 실패해 되돌려지면 파일이 남아 있어야 하기 때문이다.
  - `UserService.passwordMatches`, `UserService.delete`
- 각 Repository의 `@Modifying` 일괄 삭제 쿼리. 처리자를 비우는 것은 `update`다.
- `AuthController.withdraw`: 서비스를 부른 뒤 지금 요청의 `HttpSession`을 무효화하고 보안 컨텍스트를 비운다.
- `ApiExceptionHandler`: `InvalidWithdrawalException`은 400

### 테스트: `WithdrawalTest` (실제 PostgreSQL, 보안 필터, 세션 저장소, 파일 저장소)

1. 로그인 없이는 401이다. 비밀번호가 틀리면 400이고 여전히 로그인되어 있다.
2. 운영자는 400이다.
3. **전부 지우는지와 남의 것은 남기는지 함께 확인한다**
   - 떠나는 회원이 두 기기에서 로그인한 상태에서 다음을 준비한다: 동영상(실제 파일), 방송, 남의 방송에 쓴 댓글, 내 콘텐츠에 남이 단 댓글 둘, 보낸 후원과 받은 후원, 신고, 유튜브 키
   - 탈퇴하면 204가 오고 다음이 확인된다
     - 계정 0, 두 기기 모두 로그아웃, 로그인하면 401
     - 동영상·방송 404, 파일 0
     - 댓글, 후원, 신고, 유튜브 키 0
   - 남는 회원은 그대로다: 로그인 유지, 남는 댓글 1, 제3자가 남는 회원에게 보낸 후원 1
   - 같은 아이디로 다시 가입할 수 있다.

## 확인한 것 (2026-11-27, 로컬)

1. 06에서 만든 `agreetest1` 계정으로 동영상을 하나 올리고 그 동영상에 댓글을 달았다(원본 파일 확인).
2. 로그아웃된 브라우저로 `/account`를 열면 로그인 화면(`/login?next=/account`)으로 갔다.
3. 로그인 후 `/account`: 아이디, 닉네임, 지워지는 것 목록이 보였다.
4. 틀린 비밀번호로 탈퇴하기를 누르자 "비밀번호가 올바르지 않습니다."가 나오고 화면이 그대로였다.
5. 올바른 비밀번호로 탈퇴하자 "탈퇴했습니다. 계정과 기록을 모두 지웠습니다…" 안내가 나오고 머리글이 로그인 전 상태로 바뀌었다.
6. DB에서 계정 0, 동영상 0, 댓글 0, 세션 0이었다. 디스크(`server/data`)에서 그 동영상 파일도 0개였다.

**아직 확인하지 않은 것**
- 앱 화면에서 탈퇴하는 것(빌드, clippy, 테스트만 확인)
- 진행 중인(LIVE) 방송이 있는 회원이 탈퇴할 때 시청자 화면이 끊기는 모습(같은 경로인 방송 삭제와 동작이 같다)

## 한계

- 변환 워커가 처리 중인 동영상을 지우면, 워커가 결과를 쓰려다 실패할 수 있다. 소유자가 동영상을 지울 때와 같은 기존 동작이다.
- 탈퇴한 회원이 받은 후원은 상대방 내역에서도 사라진다. 실제 결제를 시작하면 법에 따른 보관 기간 때문에 이 규칙을 바꿔야 한다(후원 기록은 남기고 회원만 익명 처리).

## 영상 시나리오 메모

1. 왜 필요한가: Google Play "앱과 웹 양쪽에서 계정 삭제", 정지는 삭제가 아니다
2. 무엇을 지울까: 외래 키를 따라가 보면 회원 하나에 걸린 것이 이렇게 많다(표). "전부 지우기"를 고른 이유
3. 순서가 중요하다: 쓴 댓글 → 후원 → 신고 → 방송 → 동영상 → 계정, 파일은 커밋 뒤
4. 시연: 내 계정 → 지워지는 것 목록 → 틀린 비밀번호 → 올바른 비밀번호 → 완료 화면 → DB와 디스크에서 0
5. 테스트 장면: "떠나는 회원"과 "남는 회원"을 나란히 두고, 지워진 것과 남은 것을 확인한다
6. 정리: 스토어 심사 준비 A-1, A-3, A-4, B-7, B-8 완료. 남은 것은 차단(Play), 오류 안내, MSIX 패키징
