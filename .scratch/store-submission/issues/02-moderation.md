# 02. 운영자 조치 (신고 처리, 콘텐츠 내리기, 계정 정지)

Status: resolved (2026-11-27, 브랜치 `content-report`, 아직 커밋 전)

스토어 심사 준비(`../spec.md`)의 A-3 항목이다. 01(신고)에 이어지는 편이다. 나중에 영상으로 만들 때 이 문서를 대본 재료로 쓴다.

## 한 줄 요약

운영자가 웹의 **신고 관리 화면**에서 신고를 대상별로 보고, **내리기(숨김)**, **문제없음(기각)**, **작성자 정지**를 할 수 있게 했다.

## 왜 만들었나

- 01에서 신고를 받게 됐지만, 받은 신고를 처리할 수단이 없었다.
- Microsoft Store Policies 7.20의 **11.12 사용자 생성 콘텐츠** 조항은 다음을 요구한다.
  - 신고된 콘텐츠를 **검토하고 내릴 수 있어야** 한다.
  - Microsoft가 요청하면 특정 콘텐츠를 내려야 한다.
- Google Play UGC 정책도 신고에 대응하는 운영(moderation)을 요구한다. 불쾌한 콘텐츠 신고를 계속 처리하지 않으면 위반이다.
- 작업 전 상태: 서버, 웹, 앱 어디에도 운영자 개념이 없었다. 콘텐츠는 Owner만 지울 수 있었다.

## 정한 규칙 (사용자와 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 조치 범위 | 내리기 + 기각 + **계정 정지·해제** | 같은 사람이 반복해서 위반하면 콘텐츠만 내려서는 막을 수 없다 |
| 조치 화면 | **웹 관리자 화면** (`/admin/reports`) | 실제로 쓸 수 있고 영상 시연에도 보여 주기 좋다. 앱에는 넣지 않았다 |
| 운영자 지정 | **DB 역할 컬럼** (`app_user.role = 'ADMIN'`) | 나중에 운영자가 여럿이 되거나 화면에서 지정할 때 유리하다 |
| 내리기의 의미 | 지우지 않고 **숨김**(`hidden_at`) | 기록과 증거가 남는다. Owner를 포함해 누구에게도 404로 보인다 |
| 방송을 내리면 | 진행 중이면 **끝낸다** | 숨긴 방송이 계속 송출되면 안 된다 |
| 정지하면 | 로그인 차단 + **로그인된 세션 모두 끊기** + 진행 중인 방송 끝내기 | 정지가 바로 효과를 내야 한다. 이미 올린 콘텐츠는 남기고, 신고된 것만 따로 내린다 |
| 운영자 정지 | 불가(400) | 실수로 운영자끼리 막는 일을 피한다 |
| 신고 묶기 | 대상별로 한 장의 카드. 조치하면 그 대상의 처리 전 신고가 한꺼번에 닫힌다 | 같은 댓글에 신고가 10건 와도 한 번만 처리하면 된다 |

## 서버 (Spring Boot)

### DB: `V9__add_moderation.sql`

- `app_user.role` (`USER`/`ADMIN`, 기본 `USER`), `app_user.suspended_at`
- `broadcast.hidden_at`, `video.hidden_at`, `comment.hidden_at`
- `report.status` (`OPEN`/`ACTIONED`/`DISMISSED`), `resolved_at`, `resolved_by`(처리한 운영자)
- 처리 전 신고를 빨리 찾기 위한 `report (status, created_at)` 인덱스

### API (운영자만, `/api/admin/**`)

| 요청 | 하는 일 |
|---|---|
| `GET /api/admin/reports` | 처리 전 신고를 대상별로 묶어 오래된 순으로. 대상 요약(제목이나 댓글 본문), 댓글이면 달린 방송·동영상, 소유자와 정지 여부, 사유별 건수, 신고 목록(신고자, 사유, 메모, 시각) |
| `POST /api/admin/reports/{type}/{id}/hide` | 대상을 숨기고 신고를 `ACTIONED`로 닫는다 |
| `POST /api/admin/reports/{type}/{id}/dismiss` | 신고만 `DISMISSED`로 닫는다 |
| `POST /api/admin/users/{id}/suspend` | 정지. 세션을 끊고 진행 중인 방송을 끝낸다 |
| `POST /api/admin/users/{id}/unsuspend` | 정지 해제 |

- 운영자가 아니면 403 "운영자만 할 수 있습니다.", 로그인하지 않았으면 401
- 정지된 사람이 로그인하면 403 "운영 정책 위반으로 정지된 계정입니다."
- `GET /api/auth/me`의 `user.admin`으로 웹이 메뉴를 보여 줄지 정한다

### 숨김이 적용되는 곳

- 방송: 라이브 목록, 최근 종료 목록, 상세, 시청 허가(MediaMTX), 송출 허가
- 동영상: 목록, 상세
- 댓글: 동영상 댓글 목록과 개수, 방송 댓글 목록, 수정·삭제·신고
- 운영자 화면은 숨긴 것도 찾는다(`findIncludingHidden`).

### 코드

- `user/UserRole.java`, `user/User.java`(역할, 정지), `user/CurrentUser.java`
  - 운영자면 `ROLE_ADMIN` 권한을 준다.
  - 정지된 계정은 `isAccountNonLocked = false`라서 Spring Security가 로그인을 막는다.
- `moderation/ModerationService.java`
  - 신고 묶기, 내리기, 기각, 정지, 해제
  - 세션은 Spring Session의 `FindByIndexNameSessionRepository`로 아이디별로 찾아 지운다.
- `web/admin/ModerationController.java`: 운영자 API
- `web/SecurityConfig.java`: `/api/admin/**`는 `hasRole("ADMIN")`. 거부될 때 운영자 API면 "운영자만 할 수 있습니다." 문구를 쓴다.
- `web/ApiExceptionHandler.java`: `LockedException`은 403 정지 문구, `InvalidModerationException`은 400
- `broadcast`·`video`·`comment` 서비스와 저장소: `hide()`, `findIncludingHidden()`, 목록 쿼리에서 숨김 제외
- `report/Report.java`, `ReportStatus.java`, `ReportService.java`: 처리 상태, `listOpen()`, `resolveOpen()`

### 테스트: `ModerationTest.java` (실제 PostgreSQL, 보안 필터, 세션 저장소)

- 로그인 안 하면 401, 일반 회원은 403, 운영자만 200. `me.admin`이 맞게 나온다.
- 같은 댓글에 신고 3건이 오면 카드 1장, 3건, 욕설·혐오 2건, 작성자와 달린 방송이 나온다.
- 방송을 내리면 누구에게나 404이고, 상태는 ENDED가 되며, 목록에서 빠진다. 방송자는 새 방송을 시작할 수 있다.
- 댓글을 내리면 목록에서 빠지고 다시 신고할 수 없다(404).
- 기각하면 콘텐츠는 그대로이고 신고는 DISMISSED가 된다.
- 정지하면 기존 세션이 끊기고, 로그인하면 403이고, 진행 중인 방송이 끝난다. 해제하면 다시 로그인할 수 있다.
- 운영자는 정지할 수 없다(400).
- 서버 전체 테스트 72개 통과(2026-11-27)

## 웹 (React)

- `pages/AdminReportsPage.tsx` (`/admin/reports`)
  - 카드 한 장이 대상 하나다. 종류 배지(방송·동영상·댓글), 신고 건수, 사유별 건수, 내용, 작성자(정지됨·숨김 배지), "보기"(댓글이면 "댓글이 달린 곳 보기") 링크, 신고 목록을 보여 준다.
  - 버튼은 **내리기**(한 번 더 확인), **문제없음**, **작성자 정지**(한 번 더 확인) 또는 **정지 해제**다.
  - 내리기나 문제없음을 누르면 카드가 사라진다. 정지하면 같은 사람의 모든 카드에 "정지됨"이 붙는다.
  - 처리할 신고가 없으면 "처리할 신고가 없습니다."가 나온다.

- `api.ts`: `Me.admin`, `fetchOpenReports`, `hideReported`, `dismissReports`, `suspendUser`, `unsuspendUser`
- `index.css`: 카드 스타일

## 운영 서버에 올릴 때

1. 배포하면 Flyway가 V9를 자동으로 적용한다.
2. 운영자 계정을 지정한다.
   ```sql
   update app_user set role = 'ADMIN' where username = '아이디';
   ```
3. 그 계정으로 **다시 로그인**한다. 역할은 로그인할 때 세션에 담긴다.
4. 계정 메뉴 → 신고 관리

## 확인한 것 (2026-11-27, 로컬)

1. 시청자 계정으로 방송과 댓글을 하나씩 신고했다(01에서 만든 데이터).
2. 새 계정을 SQL로 운영자로 지정하고 다시 로그인했다. `me.admin`이 true였다.
3. `/admin/reports`에 카드 2장이 보였다(댓글 1건, 방송 1건).
4. 댓글 카드에서 내리기 → 확인을 눌렀다. 카드가 사라졌고, DB에서 댓글 `hidden_at`과 신고 `ACTIONED`가 확인됐다. 방송 댓글 목록에서도 빠졌다.
5. 방송 카드에서 작성자 정지 → 확인을 눌렀다. "정지됨" 배지와 "정지 해제" 버튼이 나왔다. DB에서 `suspended_at`이 채워졌고, 방송은 ENDED가 됐다.
6. 정지된 계정으로 로그인하자 403 "운영 정책 위반으로 정지된 계정입니다."가 나왔다.
7. 01 이전에 로그인해 둔 세션도 그대로 쓸 수 있었다. 세션에 저장된 로그인 정보 형식이 바뀌어도 호환된다.

**아직 확인하지 않은 것**
- 동영상 내리기를 화면으로 해 보는 것(서버 코드 경로는 방송·댓글과 같다)
- 정지 해제 버튼을 화면에서 눌러 보는 것(API는 테스트로 확인했다)
- 실제 송출 중인(LIVE) 방송을 내렸을 때 시청 화면이 끊기는 모습

## 한계와 다음에 할 것

- 숨긴 동영상의 HLS 파일은 주소를 알면 계속 열린다. 주소에는 무작위 ID가 들어가고, 더 이상 어디에도 나오지 않는다. 필요하면 `/media` 요청에서 숨김을 확인한다.
- 숨김을 되돌리는 기능과 처리한 신고 이력을 보는 화면은 없다. DB에는 남아 있다.
- 운영자 화면은 웹에만 있다. 앱은 `me.admin`을 받기만 하고 쓰지 않는다.
- 운영자 지정은 SQL로만 한다.
