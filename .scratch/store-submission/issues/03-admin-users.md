# 03. 운영자 회원 관리 (회원 목록, 검색, 정지·해제)

Status: resolved (2026-11-27, 브랜치 `content-report`, 아직 커밋 전)

02(운영자 조치)를 넓힌 편이다. 나중에 영상으로 만들 때 이 문서를 대본 재료로 쓴다.

## 한 줄 요약

운영자 화면에 **회원 관리** 탭을 추가했다. 전체 회원을 보고, 아이디나 닉네임으로 찾고, 상태(이용 중·정지됨)로 거르고, 그 자리에서 정지하거나 정지를 풀 수 있다.

## 왜 만들었나

- 02에서는 신고된 콘텐츠의 작성자만 정지할 수 있었다. 신고 카드가 없으면 그 사람을 정지하거나 정지를 풀 방법이 화면에 없었다.
- 사용자 요청(2026-11-27): "회원 목록을 볼 수 있고, 해당 회원의 상태(정지/해제)를 확인하고 수정할 수 있도록"
- 누가 정지됐는지 한눈에 보고, 실수로 정지한 사람을 바로 풀 수 있어야 한다.

## 정한 규칙

| 항목 | 결정 | 이유 |
|---|---|---|
| 보이는 정보 | 닉네임, **아이디**, 운영자 여부, 정지 여부, 가입일, 정지일 | 아이디는 원래 다른 사람에게 숨기지만, 운영자는 운영자 지정 SQL 등에 아이디가 필요하다 |
| 정렬 | 최근 가입한 순, 20명씩 | 새로 들어온 계정(스팸 계정 등)을 먼저 본다 |
| 검색 | 아이디나 닉네임 **일부**, 대소문자 무시 | 닉네임만 기억하거나 아이디 일부만 알 때도 찾는다 |
| 상태 필터 | 전체 / 이용 중 / 정지됨 | 정지된 사람만 모아 볼 수 있다 |
| 조치 | 정지·해제 모두 한 번 더 확인 | 정지는 바로 로그아웃시키는 무거운 동작이다 |
| 운영자 계정 | 정지 버튼을 보이지 않음 | 서버도 거절한다(02의 규칙) |
| 화면 상태 유지 | 검색어, 상태, 쪽을 주소(`?q=&status=&page=`)에 담음 | 새로고침과 뒤로 가기에도 그대로 남는다 |

## 서버

### API

`GET /api/admin/users?q=&suspended=&page=0` (운영자만)

```json
{
  "items": [
    { "id": "…", "username": "viewer74405", "nickname": "시청자74405",
      "admin": false, "suspended": false, "suspendedAt": null, "createdAt": "…" }
  ],
  "page": 0, "totalPages": 2, "totalItems": 33
}
```

- `q`: 아이디나 닉네임 일부. 비우면 전체
- `suspended`: `true`면 정지된 회원만, `false`면 이용 중인 회원만, 없으면 전체
- 정지와 해제는 02의 `POST /api/admin/users/{id}/suspend`, `/unsuspend`를 그대로 쓴다.

### 코드

- `user/UserRepository.java`: `search(query, suspended, pageable)` JPQL. `lower(...) like '%q%'`로 아이디와 닉네임을 찾고, 정지 여부를 거른다.
- `user/UserService.java`: `search()`. 검색어를 다듬고, 최근 가입한 순(같으면 ID 순)으로 20명씩 가져온다.
- `user/User.java`: `getSuspendedAt()`
- `web/admin/ModerationController.java`: `GET /api/admin/users`, `UserResponse`, `UserPageResponse`

### 테스트: `ModerationTest.adminsListAndSearchUsersWithTheirStatus`

- 일반 회원은 403
- 닉네임 일부로 찾으면 1명이 나오고, 아이디·닉네임·운영자 여부·정지 여부·가입일이 맞다.
- 아이디를 대문자로 바꿔 찾아도 나온다.
- 정지하면 목록에서 `suspended: true`이고 `suspendedAt`이 채워진다.
- `suspended=true`로 거르면 정지된 회원만 나오고, 방금 정지한 회원이 들어 있다.
- 검색어 없이 보면 가장 최근에 가입한 운영자 본인이 맨 앞이고 `admin: true`다.
- 서버 전체 테스트 78개 통과(2026-11-27)

## 확인한 것 (2026-11-27, 로컬)

1. 운영자 계정으로 계정 메뉴 → 운영자 → 회원 관리 탭을 열었다. 33명이 최근 가입한 순으로 나왔다. 맨 위는 운영자 본인이고 "운영자"와 "나" 배지가 붙어 있었으며 정지 버튼이 없었다.
2. 02에서 정지한 방송자 계정에 "정지됨" 배지, 정지일, "정지 해제" 버튼이 보였다.
3. "정지됨" 필터를 누르자 주소가 `?status=suspended`로 바뀌고 1명만 나왔다.
4. 정지 해제 → "방송자74405님의 정지를 풀까요?" → 해제를 눌렀다. 배지가 사라지고 버튼이 "정지"로 바뀌었다.
5. "전체"로 돌리고 `VIEWER`(대문자)로 찾자 `viewer74405`, `demoviewer` 2명이 나왔다.

**아직 확인하지 않은 것**
- 목록에서 정지를 눌러 실제로 그 사람의 세션이 끊기는 것. 같은 API이고 02 테스트에서 확인했다.
- 휴대폰 폭 화면
- 21명이 넘을 때의 쪽 이동을 화면에서 확인하는 것

## 한계

- 검색어에 `%`나 `_`를 넣으면 SQL LIKE의 와일드카드로 해석된다. 아이디에는 이 문자가 들어갈 수 없지만, 닉네임 검색 결과가 넓어질 수 있다.
- 정지 사유는 남기지 않는다. 신고 카드에서 정지했는지, 목록에서 정지했는지도 구분하지 않는다.
- 운영자 지정과 해제는 여전히 SQL로만 한다.

## 영상 시나리오 메모

1. 문제: "신고가 없으면 이 사람을 정지하거나 풀 방법이 없다."
2. 탭이 생긴 운영자 화면: 신고 관리 ↔ 회원 관리
3. 회원 목록 훑기: 운영자·나·정지됨 배지, 가입일과 정지일
4. 필터 "정지됨" → 한 명 → 정지 해제 → 확인 → 배지가 사라짐
5. 검색: 대문자로 쳐도 찾는다. 주소에 검색어가 남아 새로고침해도 그대로다.
6. 정리: 01 신고 → 02 신고 처리 → 03 회원 관리로, 스토어가 요구하는 "신고와 운영" 묶음 완성
7. 다음 편 예고: 이용약관과 개인정보처리방침 페이지
