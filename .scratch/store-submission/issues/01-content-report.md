# 01. 콘텐츠 신고

Status: resolved (2026-11-27, 브랜치 `content-report`, 아직 커밋 전)

스토어 심사 준비(`../spec.md`)의 A-1 항목이다. 나중에 영상으로 만들 때 이 문서를 대본 재료로 쓴다.

## 한 줄 요약

로그인한 사람이 남의 **방송, 동영상, 댓글**을 사유와 함께 신고할 수 있게 했다. 서버, 웹, 앱(Windows·macOS·모바일 공통 코드)에 모두 들어갔다.

## 왜 만들었나

- 과제: 데스크톱 앱을 서명된 "안전한 앱"으로 배포한다. 무료로 하려면 Microsoft Store에 MSIX로 올리는 것이 가장 좋다.
- 누구나 방송하고, 영상을 올리고, 댓글을 쓰는 서비스라서 스토어는 **사용자 생성 콘텐츠(UGC) 앱**으로 본다.
- Microsoft Store Policies 7.20의 **11.12 사용자 생성 콘텐츠** 조항은 다음을 요구한다.
  - 앱 안에서 부적절한 콘텐츠를 **신고하는 수단**
  - 신고된 콘텐츠를 검토하고 내리는 운영 수단(다음 작업)
  - 앱과 웹에 게시한 이용약관과 가이드라인(다음 작업)
- Google Play의 UGC 정책도 "앱 안에서 콘텐츠와 사용자를 신고할 수 있어야 한다"고 요구한다. 그래서 신고는 두 스토어 모두에서 필수다.
- 작업 전 코드 확인(2026-11-27): 신고, 차단, 관리자 개념이 서버, 웹, 앱 어디에도 없었다.

## 정한 규칙 (사용자와 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 누가 | **로그인한 User만** | 로그인 없이 받으면 중복이나 장난 신고를 막기 어렵다. 로그인하지 않은 사람이 누르면 로그인 화면으로 보내고, 로그인 뒤 원래 화면으로 돌아온다 |
| 무엇을 | Broadcast, Video, Comment | 다른 사람이 보는 UGC는 이 세 가지다 |
| 사유 | 스팸·광고 / 욕설·혐오 / 성적인 콘텐츠 / 폭력·위험한 행동 / 저작권 침해 / 기타 중 하나(필수) + 자세한 내용(선택, 200자) | 운영자가 빠르게 분류할 수 있게 사유는 고정 목록으로 받고, 맥락은 메모로 받는다 |
| 몇 번 | **같은 대상은 한 사람이 한 번만** | 같은 사람이 여러 번 눌러 신고 수를 부풀리지 못하게 한다. 다시 누르면 "이미 신고했습니다"라고 안내한다 |
| 내 것 | 내 방송, 내 동영상, 내가 쓴 댓글은 신고할 수 없음 | 버튼을 아예 숨기고, 서버도 한 번 더 거절한다 |
| 대상이 지워지면 | 신고 기록은 남김 | 운영자가 나중에 확인할 수 있어야 한다. 그래서 대상 테이블에 외래 키를 걸지 않았다 |
| 클라이언트 | 앱 + 웹 둘 다 | 심사 대상은 앱이지만, 두 화면의 기능을 같게 유지한다 |

## 서버 (Spring Boot)

### API

`POST /api/reports` (로그인과 CSRF 토큰 필요)

```json
{ "targetType": "COMMENT", "targetId": "…uuid…", "reason": "HATE", "detail": "욕설이 있어요" }
```

| 결과 | 응답 |
|---|---|
| 성공 | `201 { "id": "…" }` |
| 로그인 안 함 | `401 로그인이 필요합니다.` |
| 사유 없음 | `400 신고 사유를 골라 주세요.` |
| 메모 200자 초과 | `400 신고 내용은 200자 이하여야 합니다.` |
| 알 수 없는 사유나 대상 종류 | `400 요청 형식이 올바르지 않습니다.` |
| 내 것을 신고 | `400 내가 만든 방송이나 동영상, 내가 쓴 댓글은 신고할 수 없습니다.` |
| 대상 없음 | `404` (방송·동영상·댓글을 찾을 수 없습니다) |
| 이미 신고함 | `409 이미 신고했습니다.` |

### DB: `V8__create_report.sql`

- `report` 테이블: 신고한 사람(`reporter_id`), 대상 종류와 ID, 사유, 메모, 시각
- `unique (reporter_id, target_type, target_id)`: 한 사람이 같은 대상을 한 번만 신고하도록 DB에서도 막는다
- 운영자 목록용으로 `created_at` 인덱스를 둔다

### 코드

- `report/Report.java`: 엔티티
- `report/ReportTargetType.java`, `report/ReportReason.java`: 대상 종류와 사유 enum
- `report/ReportService.java`: 규칙 확인
  1. 사유와 메모 검사
  2. 대상 찾기. 없으면 404이고, 찾으면서 대상의 Owner·Author를 알아낸다
  3. 내 것인지 확인
  4. 이미 신고했는지 확인
  5. 저장. 동시에 두 번 눌러 DB unique에 걸려도 409로 바꾼다
- `web/report/ReportController.java`: `POST /api/reports`
- `web/ApiExceptionHandler.java`: `InvalidReportException`은 400, `AlreadyReportedException`은 409
- `comment/CommentService.java`: 신고 대상 확인용 `get(id)`를 공개했다. 기존 수정·삭제도 이 메서드를 쓴다

### 테스트: `ReportTest.java` (실제 PostgreSQL 컨테이너와 보안 필터로 확인)

- 로그인 없이 신고하면 401
- 남의 방송을 신고하면 201, 다시 신고하면 409, 다른 사람은 따로 신고 가능
- 남의 댓글 신고. 메모 앞뒤 공백은 잘라서 저장
- 내 방송과 내 댓글은 400
- 없는 방송·동영상·댓글은 404
- 잘못된 사유, 잘못된 대상 종류, 사유 누락, 200자 초과는 400
- 서버 전체 테스트 통과(2026-11-27)

## 웹 (React)

- `components/ReportButton.tsx`: "신고" 글자 버튼
  - 누르면 사유 라디오 6개, 메모 입력칸, 취소·신고하기 버튼이 펼쳐진다
  - 사유를 고르기 전에는 신고하기가 비활성이다
  - 성공하면 "신고했습니다. 운영자가 확인할게요.", 중복이면 "이미 신고했습니다."가 그 자리에 뜬다
  - 내 것이면 버튼을 그리지 않는다. 로그인하지 않았으면 로그인 화면으로 가는 링크가 된다
- 붙인 곳
  - 방송 시청 화면(`LiveWatchPage.tsx`): 방송자 이름 아래
  - 동영상 상세(`VideoDetailPage.tsx`): 올린 사람과 날짜 아래
  - 댓글(`CommentItem.tsx`): 남이 쓴 댓글의 오른쪽. 동영상 댓글과 라이브 댓글이 같은 컴포넌트를 쓴다
- `api.ts`: `fileReport()`, 사유 목록과 문구(`REPORT_REASONS`), 메모 상한
- `index.css`: 신고 폼 스타일. 펼쳐지면 줄 하나를 다 쓴다

## 확인한 것 (2026-11-27, 로컬)

1. 방송자 계정으로 방송을 만들고 댓글을 남겼다.
2. 시청자 계정으로 같은 방송 화면을 열었다. 방송 아래와 댓글 옆에 "신고"가 보였다.
3. 댓글 신고 → "욕설·혐오" 선택 → "테스트 신고입니다" 입력 → 신고하기를 눌렀다. "신고했습니다. 운영자가 확인할게요."가 떴다.
4. DB `report` 테이블에 `COMMENT / HATE / 테스트 신고입니다`가 저장됐다.
5. 새로고침 후 같은 댓글을 다시 신고하자 "이미 신고했습니다."가 떴다.

**아직 확인하지 않은 것**
- 앱 화면을 실제로 띄워서 누르는 것. 빌드만 확인했다.
- 로그인하지 않은 상태의 신고 링크
- 동영상 신고 화면(서버 규칙은 테스트로 확인했다)

## 영상 시나리오 메모

1. 문제: "스토어에 올리려면 신고 기능이 필수다." 정책 문서의 11.12 조항을 보여 준다.
2. 규칙을 정하는 장면: 누가, 무엇을, 몇 번, 내 것은 안 됨(위 표).
3. 시연: 시청자 계정 → 댓글 "신고" → 사유 선택 → 메모 → 신고하기 → 완료 문구 → 다시 눌러 "이미 신고했습니다"
4. 뒤에서 일어나는 일: API 요청 하나, DB unique 제약, 응답 코드 표
5. 같은 기능이 웹과 앱에 모두 들어간 것을 나란히 보여 준다.
6. 다음 편 예고: 신고를 받았으니 이제 처리할 운영자 기능이 필요하다(A-3).
