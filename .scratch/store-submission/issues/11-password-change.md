# 11. 비밀번호 변경

Status: resolved (2026-11-27, 브랜치 `email-account`, 아직 커밋 전)

이메일 계정 묶음(08~13)의 네 번째 편이다.

## 한 줄 요약

로그인한 회원이 **지금 비밀번호만 알면** "내 계정"에서 새 비밀번호로 바꿀 수 있다. 이 기기는 로그인을 유지하고, **다른 기기의 로그인은 끊는다**.

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 확인 | 지금 비밀번호만 (사용자 요청) | 메일 확인 없이 바로 바꾼다 |
| 새 비밀번호 규칙 | 가입과 같다(8~64자). `UserService.checkPassword()` 하나로 가입·변경·재설정이 같은 규칙을 쓴다 | 규칙이 갈라지지 않게 한다 |
| 다른 기기 | 로그아웃시킨다 | 비밀번호를 바꾸는 흔한 이유가 "누가 내 계정을 쓰는 것 같다"이기 때문이다 |

## 서버

- `POST /api/auth/password {currentPassword, newPassword}` (로그인)
  - 지금 비밀번호가 틀리면 400 "지금 비밀번호가 올바르지 않습니다."
  - 새 비밀번호가 규칙에 안 맞으면 400
  - 성공하면 204
- `AccountMailService.changePassword`
  - 확인 후 새 해시를 저장한다.
  - 커밋 뒤 세션 저장소에서 같은 이메일의 세션 가운데 **지금 요청의 세션을 뺀 나머지**를 지운다.
- `AuthController`: 지금 요청의 세션 ID를 넘긴다.

### 테스트: `AccountTest.membersChangeTheirPasswordWithTheCurrentOne`

- 틀린 지금 비밀번호는 400, 짧은 새 비밀번호는 400, 로그인하지 않으면 401
- 성공하면 이 기기의 `/me`는 그대로, 두 번째 기기는 로그아웃
- 예전 비밀번호로 로그인하면 401, 새 비밀번호로 로그인하면 200

## 웹·앱

- 내 계정 "비밀번호 변경": 지금 비밀번호, 새 비밀번호(8자 이상 안내), 새 비밀번호 확인
  - 새 비밀번호 두 칸이 맞고 규칙에 맞아야 버튼이 켜진다.
  - 성공하면 칸을 비우고 "비밀번호를 바꿨습니다. 다른 기기의 로그인은 끊겼습니다."를 보여 준다.
