# 08. 회원 아이디를 이메일로 바꾸기

Status: resolved (2026-11-27, 브랜치 `email-account`, 아직 커밋 전)

이메일 계정 묶음(08~13)의 첫 편이다. 나중에 영상으로 만들 때 이 문서를 대본 재료로 쓴다.

## 한 줄 요약

로그인 아이디를 "영문 소문자·숫자 4~20자 아이디"에서 **이메일 주소**로 바꿨다. 기존 회원은 이메일이 없어서 모두 지웠다.

## 왜

- 이메일 인증(09)과 비밀번호 재설정(12)을 하려면 회원에게 연락할 주소가 있어야 한다.
- 사용자 요청(2026-11-27): "회원 아이디를 이메일로 변경, 거기에 따른 수집정보 변경"

## 정한 것 (사용자와 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 기존 회원 | **모두 삭제** | 지금 회원은 이메일이 없는 데모·테스트 계정뿐이다. 이메일을 나중에 등록하게 하는 이행 경로를 만들지 않아도 된다 |
| 저장 형태 | 앞뒤 공백을 빼고 **소문자**로 저장 | `A@B.com`과 `a@b.com`이 다른 계정이 되지 않게 한다. 로그인도 대소문자를 무시한다 |
| 형식 검사 | `무엇@무엇.무엇`만 본다(254자 이하) | 진짜 받을 수 있는 주소인지는 인증 메일(09)로 확인한다 |
| 보이는 곳 | 본인(내 계정)과 운영자(회원 관리)만 | 다른 회원에게는 닉네임만 보인다(아이디 때와 같다) |

## 서버

- `V11__email_as_login_id.sql`
  - 세션, 댓글, 신고, 후원, 방송, 동영상, 유튜브 키, 회원을 모두 지운다.
  - `app_user.username` → `email`(254자, unique, 제약 이름도 `app_user_email_key`로 바꿈)
  - **DB만 지운다. 배포할 때 미디어 저장소의 영상 파일도 직접 비워야 한다**(README "배포할 때 주의").
- `User.email`, `CurrentUser.email()`(Spring Security의 로그인 아이디 = 이메일, 세션 저장소의 principal_name도 이메일)
- `UserService`
  - `EMAIL` 패턴, `normalizeEmail()`(소문자)
  - 가입할 때 형식이 틀리면 400 "이메일 주소를 확인해 주세요."
  - 중복이면 409 "이미 가입한 이메일입니다."
  - `loadUserByUsername(email)`
- `AuthController`: 가입·로그인 요청과 `/me` 응답의 `username` → `email`. 로그인 실패 문구는 "이메일 또는 비밀번호가 올바르지 않습니다."
- 운영자 회원 목록·검색(`ModerationController`, `UserRepository.search`)도 이메일로 바꿨다.
- 정지(`ModerationService`)와 탈퇴(`WithdrawalService`)는 세션을 이메일(principal)로 찾아 끊는다.

### 테스트

- 모든 테스트의 가입·로그인 요청을 이메일로 바꿨다.
- `AccessControlTest.loginChecksThePassword`: `Login1@Example.com`으로 가입하면 `login1@example.com`으로 저장되고, 대소문자가 섞여도 로그인된다.
- `AccessControlTest.signUpRejectsBadOrDuplicateValues`: 이메일 형식이 아니면 400, `" DUP@Example.com "`처럼 공백과 대소문자만 다른 중복 주소는 409다.

## 웹·앱

- 웹
  - 로그인·가입 화면의 "아이디" 칸을 "이메일" 칸(`type=email`, `autoComplete=email`)으로 바꿨다.
  - 가입 칸 안내는 "로그인할 때 씁니다. 가입하면 인증 메일을 보냅니다. 다른 회원에게는 보이지 않습니다."
  - `api.ts`: `EMAIL_PATTERN`, `EMAIL_MAX_LENGTH`, `Me.email`, `AdminUser.email`
  - 내 계정, 운영자 회원 관리(검색 칸 "이메일이나 닉네임")
- 앱
  - 로그인·가입 화면과 내 계정
  - `api::is_valid_email()`과 단위 테스트 `checks_email_shape`
- `load-test/load.js`: 가입·로그인을 이메일로 바꿨다.

## 약관·방침

- 이용약관: "이메일 주소로 로그인", 가입 조항(인증 메일, 인증해야 업로드·댓글), 계정 관리(이메일 계정과 비밀번호), 탈퇴 요청은 "가입한 이메일 주소"로
- 개인정보처리방침
  - 수집 항목에 이메일 주소와 인증 시각을 넣었다. "이메일은 받지 않습니다" 문구는 지웠다.
  - "이메일 주소는 로그인과 인증·재설정 메일에만 쓰고 광고 메일을 보내지 않는다"
  - 이메일은 다른 회원에게 보이지 않는다.

## 확인한 것 (2026-11-27, 로컬)

- 서버를 다시 띄우자 Flyway가 V11, V12를 적용했고 로컬 회원이 0명이 됐다.
- 웹 가입 화면에서 `mailtest1@example.com`으로 가입하자 바로 로그인됐고, `/me`에 이메일이 나왔다.
- 서버 전체 테스트 통과(91개, 09~12 포함)

## 영상 시나리오 메모

1. 아이디 → 이메일: 왜 바꾸나(인증, 비밀번호 찾기)
2. "기존 회원은 어떻게?" 선택지 두 개(이행 vs 삭제)와 고른 이유
3. 대소문자 이야기: 같은 사람이 두 계정을 만들지 않게 소문자로 저장
4. 방침 바뀐 부분: "이메일은 받지 않는다" → "이메일은 로그인과 안내 메일에만"
