# 12. 비밀번호 분실 시 재설정 메일

Status: resolved (2026-11-27, 브랜치 `email-account`, 아직 커밋 전)

이메일 계정 묶음(08~13)의 다섯 번째 편이다.

## 한 줄 요약

로그인 화면의 **"비밀번호를 잊으셨나요?"**에서 이메일을 넣으면, **새 비밀번호를 정하는 링크**가 든 메일을 보낸다. 링크에서 새 비밀번호를 정하면 모든 기기의 로그인이 끊긴다.

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 가입 여부 노출 | 가입하지 않은 이메일도 **똑같이 204**("가입한 계정이 있으면 보냈습니다") | 다른 사람이 이 화면으로 어떤 이메일이 가입했는지 알아낼 수 없게 한다 |
| 링크 유효 | **30분**, 한 번만, 새로 요청하면 이전 링크 무효 | 재설정 링크는 계정을 넘겨받을 수 있는 열쇠라 인증 링크(24시간)보다 짧게 둔다 |
| 요청 빈도 | 같은 회원에게 1분에 한 번. 그 안의 요청은 조용히 무시한다(응답은 같다) | 메일 폭탄을 막으면서 가입 여부도 드러내지 않는다 |
| 정지된 계정 | 메일을 보내지 않는다 | 정지를 비밀번호 재설정으로 우회하지 못하게 한다 |
| 재설정 후 | 모든 기기 로그아웃, **이메일도 인증된 것으로 처리** | 그 메일함에서 링크를 열었으니 주소의 주인이다 |
| 화면 위치 | 웹 화면 (`/forgot-password`, `/reset-password`). 앱은 "비밀번호를 잊으셨나요?"가 웹 화면을 브라우저로 연다 | 메일 속 링크도 웹으로 온다. 한 곳에만 둔다 |

## 서버

| 요청 | 결과 |
|---|---|
| `POST /api/auth/password-reset/request {email}` (로그인 불필요) | 언제나 204. 조건이 맞으면 메일을 보낸다 |
| `POST /api/auth/password-reset {token, newPassword}` (로그인 불필요) | 204. 값이 잘못됐거나 만료·사용됐으면 400 "비밀번호 재설정 링크가 만료되었거나 이미 사용했습니다. 비밀번호 찾기를 다시 해 주세요." 새 비밀번호가 규칙에 안 맞으면 400이고, 이때 **링크는 쓰지 않은 채로 남는다** |

- `AccountMailService.requestPasswordReset`, `resetPassword`. 토큰 저장 방식(해시, 일회용)은 이메일 인증(09)과 같은 `email_token` 테이블을 쓴다.
- 메일

> 제목: [Web Broadcast] 비밀번호 재설정 링크
>
> ○○님, 비밀번호 재설정을 요청하셨습니다. 아래 링크를 눌러 새 비밀번호를 정해 주세요. 링크는 30분 동안 한 번 쓸 수 있습니다. (링크) 요청한 적이 없다면 이 메일은 무시해 주세요. 비밀번호는 바뀌지 않습니다.

### 테스트: `AccountTest`

- `forgottenPasswordsAreResetThroughAMailedLink`
  - 가입하지 않은 이메일도 204이고 메일은 없다.
  - 대문자로 넣어도 메일이 온다. 1분 안의 두 번째 요청은 204지만 메일이 없다.
  - 지어낸 값은 400이다. 짧은 비밀번호는 400이고 링크는 남는다.
  - 성공하면 204이고, 기존 로그인이 끊긴다. 예전 비밀번호는 401, 새 비밀번호는 200이다. 이메일이 인증된다. 같은 링크를 다시 쓰면 400이다.
- `suspendedMembersGetNoResetMail`: 정지된 계정에는 메일이 가지 않는다.

## 웹·앱

- 웹 `pages/PasswordResetPages.tsx`
  - `/forgot-password`: 이메일 칸, "재설정 링크 받기". 보낸 뒤 "○○로 가입한 계정이 있으면 … 보냈습니다. 링크는 30분 … 스팸함도 확인"
  - `/reset-password?token=`: 새 비밀번호와 확인. 실패하면 "비밀번호 찾기" 링크. 성공하면 "새 비밀번호로 로그인해 주세요"와 로그인 버튼
  - 로그인 화면에 "비밀번호를 잊으셨나요?" 링크
- 앱: 로그인 화면의 "비밀번호를 잊으셨나요?"가 `{웹 주소}/forgot-password`를 기본 브라우저로 연다(`config::forgot_password_url()`).

## 확인한 것 (2026-11-27, 로컬, 실제 SMTP → Mailpit)

1. 로그아웃 → 로그인 화면 → "비밀번호를 잊으셨나요?" → `MailTest1@example.com`(대문자 섞음) 입력 → 안내 화면
2. Mailpit에 재설정 메일이 왔다. 링크 `…/reset-password?token=…`
3. 링크를 열어 `resetpw12`로 바꾸자 "비밀번호를 바꿨습니다 … 다른 기기의 로그인은 모두 끊겼습니다"
4. 예전 비밀번호(`newpass12`)로 로그인하면 401, 새 비밀번호로 로그인하면 200

## 영상 시나리오 메모

1. "가입하지 않은 이메일에도 보냈다고 말하는 이유" (계정 존재 노출)
2. 30분과 24시간: 링크마다 위험이 다르다
3. 시연: 비밀번호 찾기 → Mailpit → 링크 → 새 비밀번호 → 예전 비밀번호는 거절
