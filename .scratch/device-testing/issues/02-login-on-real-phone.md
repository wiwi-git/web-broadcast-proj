# 로그인·댓글 실기기 테스트

Status: ready-for-human

회원·댓글 단계는 데스크톱 브라우저에서만 확인했다. 휴대폰에서는 `https://<LAN_IP>:5173`(자체 서명 인증서)로 접속하므로 쿠키 동작이 다를 수 있다. 준비 방법은 `01-live-broadcast-on-real-phone.md`와 같다.

## 확인할 것

- [ ] iPhone Safari, Android Chrome에서 회원가입·로그인이 되고, 새로고침해도 로그인이 유지된다 (세션 쿠키)
- [ ] 로그인한 뒤 방송 시작·종료가 된다 (CSRF 토큰 쿠키가 HTTPS LAN 주소에서도 저장되는지)
- [x] 로그인하지 않고 `/broadcast`에 들어가면 로그인 화면으로 갔다가, 로그인 후 방송 화면으로 돌아온다 (2026-11-18, iOS 26.3 시뮬레이터 Safari)
- [x] 휴대폰 시청 화면에서 댓글 입력칸을 누르면 키보드가 댓글 목록을 가리지 않는다 (2026-11-18, 시뮬레이터. 화면 확대도 없음)
- [x] 방송 중 다른 기기에서 쓴 댓글이 3초 안에 보인다 (2026-11-18, 시뮬레이터 ↔ Mac 브라우저 양방향, 약 2초)
- [ ] 방송자가 휴대폰에서 방송하는 동안 PC에서 같은 계정으로 "방송 종료"를 누르면 휴대폰 화면도 종료로 바뀐다

## Comments

2026-11-18, iOS 26.3 시뮬레이터 Safari(`http://localhost:5173`)로 확인:
- 회원가입 후 주소를 새로 열어도 로그인이 유지된다(iPhone 쪽). Android Chrome은 아직이라 첫 항목은 열어 둔다.
- 처음 열었을 때 한글이 모두 `?` 상자로 나왔다. iOS가 `system-ui`가 앞에 있으면 한글을 다음 글꼴로 넘기지 못하는 문제로, 앱(app/assets/main.css)에서만 고쳐져 있었다. 웹 CSS에도 한글 글꼴을 맨 앞에 두어 고쳤다.
- 같은 앱 커밋의 "입력칸 16px 미만이면 확대" 대응도 웹에 옮겼다(터치 기기만).
- 휴대폰 폭(402pt)에서 머리글 메뉴 글자가 "라…", "동…"처럼 한두 글자로 잘린다. 설계대로 줄이는 것이지만 알아보기 어렵다.
