- 08:13:45 `docker kill wb-worker-check-worker-1` (SIGKILL, 점유를 풀 기회 없음)
- 08:14:42 `worker-3` 로그: `Video ac863d17-… 변환 시작`
- 08:14:56 `worker-3` 로그: `Video ac863d17-… 공개 (14초 소요)`, DB 상태 `PUBLISHED`
- 강제 종료부터 다른 워커가 시작하기까지 **약 57초**. 점유 기한(60초)이 지난 뒤 다음 폴링에서 가져갔다.

## 변환 실패 (종료 코드 137)

- 워커 설정: 메모리 한도 1GiB, `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75`(JVM 최대 힙 비율 설정이며, 실제 사용량은 측정하지 않았다).
- 1080p 90초 영상 8개가 모두 `FAILED`. 워커 로그: `TranscodeException: ffmpeg 종료 코드 137`(SIGKILL로 끝났다는 뜻).
- 쿠버네티스 OOM 이벤트나 커널 로그는 확인하지 않았다. 그래서 원인은 **메모리 부족으로 추정**했다.
- 최대 힙 20%, 한도 2GiB로 바꾼 뒤 같은 1080p 영상 6개가 모두 공개됐다(위 기록).
