이번 과제는 도메인을 사서 오라클 클라우드에 서비스를
배포하고, 윈도우와 맥 앱까지 만드는 것입니다.
결과부터 보면, duse.dev라는 도메인 아래에서
라이브 방송 서비스가 HTTPS로 동작합니다.
도메인, 서버, 배포, 그리고 데스크톱 앱
순서로 어떻게 만들었는지 설명드리겠습니다.
먼저 도메인입니다.
Cloudflare Registrar에서
duse.dev를 샀습니다.
Cloudflare는 도메인을 원가에
팔고 DNS 관리도 무료라서 골랐습니다.
첫해만 싼 도메인이 많아서, 갱신 가격까지 보고 정했습니다.
.dev 도메인에는 특징이 하나 있습니다.
브라우저가 HTTPS로만 접속하도록 강제합니다.
그래서 인증서가 처음부터 필수였고,
이건 뒤에서 볼 Caddy로 해결합니다.
DNS에는 A 레코드를 두 개 넣었습니다.
@는 duse.dev 자체를,
*는 live.duse.dev 같은
모든 서브도메인을 가리킵니다.
* 와일드카드는 도메인 자체를
포함하지 않기 때문에 둘 다 필요합니다.
그리고 Cloudflare의 프록시는 껐습니다.
방송에 쓰는 WebRTC 미디어는
프록시를 통과할 수 없고, 엔터프라이즈가
아닌 요금제는 영상을 대량으로 전달하는
용도를 약관으로 제한하기 때문입니다.
이제 어떤 서브도메인을 조회해도 같은 서버 주소가 돌아옵니다.
다음은 서버입니다.
오라클 클라우드, 줄여서 OCI의 상시 무료 서버를 썼습니다.
OCI의 자원은 몇 겹으로 담겨 있습니다.
가장 바깥은 리전이고, 도쿄 리전을 골랐습니다.
리전 안의 데이터센터를 가용성 도메인이라고
하는데, 도쿄는 이것이 하나뿐입니다.
그래서 자리가 없으면 다른 곳으로 피할 수 없습니다.
자원은 컴파트먼트라는 폴더에 담깁니다.
이 프로젝트는 기본 컴파트먼트 하나만 씁니다.
서버가 사는 가상 네트워크는 VCN입니다.
그 안에 공인 서브넷을 두고,
인터넷 게이트웨이로 밖과 연결합니다.
인스턴스를 만드는 화면에서 네트워크를
함께 만들면 공인 IP 스위치가
잠겨 있어서, VCN 마법사로 네트워크를 먼저 만들었습니다.
서버 자체는 인스턴스이고, 사양은 셰이프로 정합니다.
무료로 쓸 수 있는 건 ARM 프로세서를
쓰는 A1.Flex 셰이프입니다.
처음에는 도쿄에 남은 자리가 없다는 오류가 계속 났고,
가장 작은 1 OCPU,
메모리 6GB로 겨우 만들 수 있었습니다.
ARM 서버라서 Docker 이미지도
arm64용이어야 합니다.
디스크는 부트 볼륨, 고정 주소는 공인 IP이고,
접속은 비밀번호 대신 SSH 키로 합니다.
마지막으로 방화벽이 두 겹입니다.
OCI의 보안 목록이 서버 바깥에서,
우분투의 iptables가 서버 안에서 막습니다.
우분투 이미지는 SSH용 22번 포트만
열어 두기 때문에, 80번,
443번, 그리고 방송용 8189번 포트를
두 곳 모두에서 열어야 접속됩니다.
비용이 나가지 않게 안전장치도 세 가지 걸었습니다.
무료 셰이프만 만들 수 있게 하는 할당량 정책,
1센트라도 청구되면 오는 예산 알림,
그리고 한 달 내내 보내도 무료 송신량을
넘지 않도록 묶은 초당 29Mbit 송신 상한입니다.
이제 배포입니다.
서버 맨 앞에는 Caddy라는 웹 서버를 두었습니다.
Caddy는 리버스 프록시입니다.
443번 포트 하나로 모든 요청을 받아서,
주소와 경로를 보고 안쪽의 알맞은 서비스로 넘겨 줍니다.
Caddy의 가장 큰 장점은 자동 HTTPS입니다.
설정 파일에 도메인만 적으면 Let's Encrypt 같은
공개 인증 기관에서 인증서를 받아 오고,
만료되기 전에 알아서 갱신합니다.
실제 인증서를 확인해 보면 발급자가
Let's Encrypt입니다.
HTTP로 들어오면 HTTPS로, www가
붙은 주소는 본래 주소로 자동으로 옮겨 줍니다.
방송 서비스인 live.duse.dev는
경로마다 가는 곳이 다릅니다.
API와 미디어 요청은 Spring 서버로 갑니다.
시청용 HLS는 앞의 접두사를 떼고 미디어 서버로 넘깁니다.
미디어 서버가 돌려주는 리다이렉트
주소에는 접두사를 다시 붙입니다.
방송 송출인 WHIP도 접두사를 떼고 미디어 서버로 갑니다.
미디어 서버만 쓰는 내부 API는 밖에서 부르면 404로
막고, 나머지 경로는 React 앱을 돌려줍니다.
저장소의 배포 안내는 원래 nginx 기준이었지만, 인증서를
따로 관리하지 않아도 되고 설정도
짧아서 Caddy를 골랐습니다.
서비스들은 docker compose로 띄웠습니다.
운영용 설정에서 데이터베이스는 밖으로 열지 않고,
나머지 내부 포트는 127.0.0.1에만 묶었습니다.
Docker가 연 포트는 서버의
iptables 규칙을 우회하기 때문에,
이렇게 묶어야 Caddy를 거쳐서만 들어올 수 있습니다.
데이터베이스 비밀번호 같은 비밀값은 저장소가
아니라 서버의 .env 파일에만 둡니다.
이렇게 배포한 사이트에서 데모 방송을 라이브로
보고, 업로드한 동영상도 재생할 수 있습니다.
도메인 하나에 서비스를 여러 개 붙일 수도 있습니다.
duse.dev 첫 화면에는 이 서버의 서비스와 상태가
카드로 보이고, 단축 주소 서비스는 다른 프로젝트입니다.
새 서비스는 서브도메인과 Caddy 설정 한 블록만 더하면
되고, 서비스를 켜고 끄는 명령도 만들어 두었습니다.
마지막은 데스크톱 앱입니다.
Rust의 Dioxus로 만든 코드 하나로
윈도우와 맥 앱을 함께 만듭니다.
화면은 각 운영체제의 웹뷰가 그리고,
웹과 같은 서버 API를 씁니다.
GitHub Actions가 버전 태그를 받으면
윈도우용 MSI와 맥용 DMG를 빌드해서 릴리스에 올립니다.
다운로드 페이지는 live.duse.dev에
두었고, 실제 파일은
GitHub Releases에서
받게 해서 서버 송신량을 쓰지 않습니다.
맥에서는 DMG로 설치한 앱으로
라이브 방송과 동영상을 볼 수 있습니다.
윈도우에서도 같은 앱으로 라이브
방송과 동영상을 볼 수 있습니다.
정리하면, 도메인을 사서 DNS를 연결하고,
OCI 무료 서버의 방화벽을 열고,
Caddy로 HTTPS와 경로를
나눠 docker compose 서비스를 배포했습니다.
그리고 같은 서버 API를 쓰는
윈도우와 맥 앱을 빌드했습니다.
감사합니다.
