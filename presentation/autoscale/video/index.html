서버를 늘리는 순간 데이터가 갈라지기 때문입니다.
먼저 기존 구조입니다.

영상 파일은 서버의 로컬 디스크에 저장했습니다.
서버 한 대일 때는 단순하고 잘 동작하는 구조였습니다.
그런데 이 서버를 그대로 여러 대로 늘리면 문제가 생깁니다.
첫째, 변환은 CPU를 많이 쓰는 작업이라,
업로드가 몰리면 같은 서버의 API 응답까지 느려집니다.
둘째, 대기열이 서버 메모리에 있어서, 각 서버는
자기가 받은 업로드만 처리하고 일을 나눠 갖지 못합니다.
셋째, 서버가 재시작할 때마다 처리 중인 영상을 모두 다시

넷째, A 서버의 디스크에

다행히 로그인 세션과 데이터는
처음부터 데이터베이스에 두었기 때문에,

첫 번째 변화는 영상 변환을 별도의 워커로 떼어낸 것입니다.

API 서버는 이제 업로드를 받으면 파일을 저장하고,

누구에게 일을 넘기지도, 결과를 돌려받지도 않습니다.

서버와 워커가 서로를 모르기 때문에,
